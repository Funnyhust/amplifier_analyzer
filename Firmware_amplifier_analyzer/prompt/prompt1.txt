PHẦN CỨNG HIỆN TẠI
MCU:
- STM32F103C8T6
- Dùng USB CDC để giao tiếp với PC
- Dùng 2 bộ SPI riêng:
  1. SPI_DAC: giao tiếp DAC MCP4822
  2. SPI_ADC: giao tiếp ADC ADS7861
- Không dùng chung SPI cho ADC và DAC nếu base hiện tại đã tách được 2 bus.
- Dùng Timer phần cứng để tạo nhịp update DAC và sample ADC.
- Ưu tiên dùng DMA nếu base đã có hoặc nếu có thể triển khai ổn định.
- Không dùng delay/polling cho luồng realtime phát/đo.

DAC:
- Chip DAC: MCP4822
- Giao tiếp SPI, gửi word 16-bit
- Có 2 kênh nếu cần, nhưng trước mắt ưu tiên kênh đang dùng trong base
- MCP4822 có gain bit:
  + GA = 1: gain x1, dải lý tưởng 0–2.048 V
  + GA = 0: gain x2, dải lý tưởng 0–4.096 V
- SHDN = 1 để bật output
- SPI frame 16 bit gồm config bits + 12-bit data
- Cần tạo driver rõ ràng:
  + mcp4822_init()
  + mcp4822_write_raw(channel, gain, code)
  + mcp4822_set_voltage_mv(channel, gain, mv)
  + mcp4822_build_frame(channel, gain, code)

ADC:
- Chip ADC: ADS7861
- Giao tiếp bằng SPI riêng
- ADC dùng để đo 2 tín hiệu, ưu tiên simultaneous sampling nếu phần cứng/base đã hỗ trợ.
- Cần tạo driver rõ ràng:
  + ads7861_init()
  + ads7861_start_conversion()
  + ads7861_read_raw()
  + ads7861_read_pair()
  + ads7861_raw_to_voltage()
- Nếu base đã có timing CONVST/RD/CS riêng thì phải giữ đúng theo base, không tự ý đổi chân.
- Nếu chưa rõ mode đọc của ADS7861 trong base, hãy đọc code và schematic/comment hiện tại để bám theo cách đang dùng.

USB:
- USB CDC device
- PC app gửi command xuống STM32
- STM32 trả response, status, dữ liệu đo, kết quả xử lý hoặc raw sample block
- Không stream raw liên tục quá lớn nếu làm nghẽn USB FS.
- Nên hỗ trợ cả chế độ:
  1. trả kết quả đã xử lý
  2. trả sample block khi cần debug/phân tích trên app

LUỒNG REALTIME FIRMWARE
Thiết bị cần chạy theo luồng:

1. PC app gửi cấu hình:
   - tần số tín hiệu
   - biên độ
   - offset nếu có
   - waveform type: sine/square/triangle/DC
   - số mẫu mỗi chu kỳ hoặc sample/update rate
   - DAC gain x1/x2
   - range DAC nếu phần cứng có
   - range ADC nếu phần cứng có
   - thời gian đo hoặc số mẫu cần thu

2. STM32 chuẩn bị waveform table:
   - Với sine 20 kHz, nếu dùng bộ hiện tại thì mặc định nên dùng 200 kSPS, tương đương 10 mẫu/chu kỳ.
   - Cho phép cấu hình sample rate, nhưng phải validate:
     + MCP4822 settling time khoảng 4.5 µs, nên không khuyến nghị update quá 200 kSPS nếu cần chính xác.
     + Nếu user chọn quá cao, firmware/app cần cảnh báo.

3. Timer tạo tick đều:
   - Mỗi tick update DAC sample tiếp theo
   - Trigger/read ADC theo timing phù hợp
   - Lưu dữ liệu ADC vào buffer vòng hoặc double buffer

4. Khi đủ block mẫu:
   - Tính nhanh RMS, peak, peak-to-peak, min, max, mean, frequency estimate nếu đủ
   - Có thể gửi raw block về app nếu app yêu cầu
   - Trả status rõ ràng

5. Stop test:
   - Dừng timer
   - Dừng DMA nếu có
   - Đưa DAC về mức an toàn, ví dụ 0 V hoặc giữ mức cuối tùy config
   - Trả summary về PC

YÊU CẦU VỀ SAI SỐ VÀ PHÂN TÍCH
Firmware và app cần hiển thị/cảnh báo các nguồn sai số chính:
1. DAC offset error
2. DAC INL/DNL
3. DAC gain/VREF error
4. DAC settling time
5. ADC quantization
6. ADC gain/offset
7. Sai số do số mẫu/chu kỳ

Công thức quan trọng:
- Số mẫu trên chu kỳ:
  N = Fs / Fsignal

- Sai số bắt hụt đỉnh nếu đo peak bằng ADC:
  Error_peak = 1 - cos(pi / N)

- Suy hao do DAC zero-order hold:
  Error_zoh = 1 - sin(pi / N) / (pi / N)

App cần tính và hiển thị các giá trị này theo cấu hình sample rate/tần số hiện tại.

Ví dụ với 20 kHz:
- 200 kSPS: N = 10 mẫu/chu kỳ
  + Error_peak ≈ 4.89%
  + Error_zoh ≈ 1.64%
- 500 kSPS: N = 25 mẫu/chu kỳ
  + Error_peak ≈ 0.79%
  + Error_zoh ≈ 0.26%
- 1 MSPS: N = 50 mẫu/chu kỳ
  + Error_peak ≈ 0.20%
  + Error_zoh ≈ 0.066%

Với bộ hiện tại MCP4822, ưu tiên ổn định ở 200 kSPS trước vì settling DAC khoảng 4.5 µs.

CALIBRATION
Cần triển khai cơ chế calib riêng cho từng dải DAC/ADC.

DAC calibration:
- Calib theo công thức:
  Vreal = a * code + b
- Từ 2 điểm đo:
  a = (V2 - V1) / (Code2 - Code1)
  b = V1 - a * Code1
- Khi cần phát điện áp:
  code = round((Vtarget - b) / a)
- Lưu a,b vào Flash.
- Nếu có nhiều range/gain:
  + dac_gain_x1_a/b
  + dac_gain_x2_a/b
  + dac_low_range_a/b nếu có chia dải ngoài
  + dac_high_range_a/b nếu có

ADC calibration:
- Calib theo công thức:
  Vinput = m * raw + c
- Từ 2 điểm chuẩn:
  m = (V2 - V1) / (Raw2 - Raw1)
  c = V1 - m * Raw1
- Lưu hệ số riêng từng kênh, từng range:
  + adc1_range_low_m/c
  + adc1_range_mid_m/c
  + adc1_range_high_m/c
  + adc2_range_low_m/c
  + adc2_range_mid_m/c
  + adc2_range_high_m/c

Cần có command USB để:
- đọc hệ số calib
- ghi hệ số calib
- reset calib default
- export/import calib nếu app hỗ trợ

GIAO THỨC USB CDC

OK

YÊU CẦU APP VỀ PHÂN TÍCH SAMPLE RATE
App phải tự tính:
- Chu kỳ tín hiệu
- Số mẫu/chu kỳ
- Sai số peak do lấy mẫu
- Suy hao ZOH nếu xét phát DAC
- Cảnh báo nếu:
  + N < 10: waveform quá thô
  + N = 10: chỉ phù hợp POC, sai số peak khoảng 4.89%
  + N >= 25: tốt hơn cho đo peak
  + MCP4822 update interval < 4.5 µs: cảnh báo DAC settling không đảm bảo

Ví dụ:
Fsignal = 20 kHz
Fs = 200 kSPS
N = 10
Hiển thị:
- Period = 50 µs
- Sample interval = 5 µs
- Samples/cycle = 10
- Peak sampling error ≈ 4.89%
- DAC ZOH droop ≈ 1.64%
- MCP4822 settling margin: borderline, vì settling ≈ 4.5 µs
